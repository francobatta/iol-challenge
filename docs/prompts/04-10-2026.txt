The task is to create a go REST API which will be a frontend (not in the UI sense, but the
  API/contract sense) for a notifications service. For now, the notification registration and
  sending flow is not to be coded.

  First, let's add a user CRUD API plus the logic of clients (owners of users) and its relation.
  The user entity will be comprised of:
  app_id, user_id, created_at. PK is (app_id, user_id)
  Each user may have one or more devices, ways to receive notifications or associated data to use
  in each notification:
  app_id, user_id, endpoint_id, address (string), channel, provider
  where PK is (app_id, endpoint_id)

  Each app has a unique ID and can create and own "lists of users" to send notifications in a
  customizable way. Lists are an entity, ALWAYS associated with an app_id:
  (app_id, list_id, name, description, created_at) where PK is (app_id, list_id)

  and users 'enter' lists by the table:
  list_members (app_id, list_id, user_id, added_at) where PK is (app_id, list_id, user_id)
  
  To recap, the task is to create the REST API endpoints, handlers, services and repos (assume
  postgres) for this requirement. Use go style, prefer simplicity and readability, and interview
  me for gaps, ambiguities or potential assumptions.
  ***
  Each app authenticates to this application using a lightweight JWT (its api key) which
     resolves to app_id accordingly
